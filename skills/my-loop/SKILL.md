# my-loop

**流程的钱，只花在「不做就发现不了」的地方。** 其余全砍。

每加一个环节，先回答：**这一步能发现什么？不做的话，那件事会以什么方式漏过去？**
答不上来，这一步就是仪式，删掉。

> 这份文件只写**你（主 agent）的判断**。干活的规矩在角色卡里
> （`my-loop-builder` / `my-loop-auditor`），**一条规矩只写一处** —— 写两处必漂。

---

## 0. 地基：错误分两类

| | 例子 | 怎么对付 |
|---|---|---|
| **会自己暴露的** | 按钮点不动、白屏、数字算错 | **竖切**让它早暴露。**不花流程成本。** |
| **不会自己暴露的** | 两个设备互相覆盖、密钥被写进正文流出去、越权读到别人数据、做完了人说「我要的不是这个」 | **流程预算 100% 花在这里** |

第二类的共同点是**没有反馈回路**。对第一类上流程是纯浪费，对第二类不上流程是纯赌博。

## 1. 先分级，再动手

| 分级 | 怎么做 |
|---|---|
| `trivial` | **直接改完**，不进循环、不写文件、不加载本手册。做完提一句 |
| `minor` | 走四步，但第 2 步压成 3 分钟自问，不派子代理 |
| `major` | 完整四步 |

**升 `major` 的信号**（命中任一不许判 minor）：动数据模型 / 鉴权权限 / 对外接口 / 钱和隐私 /
新建模块 / 跨 3 个以上模块 / 与决策表冲突。

判不准就问：**这个改动如果出错，最坏会怎样？** 不影响别人 → trivial；
影响本模块 → minor；影响契约、数据、权限 → major。

分级必须说出来。**对 trivial 套流程是这套方法论最常见的死法** ——
人会开始绕开它，然后重要的改动也一起绕开。

---

## 2. 四步

### ① 对齐锚（15 分钟，minor / major 一律强制）

逼出**一句业务验收标准**：不是「接口返回 200」，是「用户干了什么、然后看到什么」。
拆成 5–8 条 `A1…An`，写进 `.my-loop/CURRENT.md`。

- 每条锚当场写上**到时候拿什么验**（命令或操作）—— 验不了的锚当场现形，
  别拖到第④步才变成「没法验」。
- 写明**这次明确不做什么** —— 范围理解不一致，事前挡住比第④步事后抓便宜。
- **必须包含用户能直接感知的运行条件**（例如「一条命令能跑起来」）—— 最容易被漏掉的一类。
- 先读决策表：有没有和已拍板的冲突？有就当场说。
- **人点头才动手，不设例外。** 复述得再有把握也要摆出来等确认；人不认就改锚再摆，
  直到人说「理解对了」。这一步押的是「方向做错了」——
  全流程最贵、且完工之前不会自己暴露的那个错误。

### ② 反例（20 分钟，全场性价比最高的一步）

只回答：**这套设计在什么输入下会塌？** 三类各至少 3 条 ——
**边界值** / **并发与重试**（含「响应丢了客户端重试」）/ **失败路径**。

输入必须包含决策表和历史踩过的坑。每条当场定：**挡住** 或 **接受并写进已知限制**。
挡住的要落成硬约束 + 一个守卫。

### ③ 竖切执行

一件活 = 从用户点得到的动作，一路到数据落地。
自检：**这件做完，人能亲眼看到什么变化？** 答不出来就是切错了。

**同一时刻只有一条竖切在做。** 竖切表每条带**怎么验**（可执行命令）和状态：
`未动 → 在做 → 过`，卡住的单独标出来。**「过」只能贴着验证命令的真实输出标**，
标上就不许改回来。状态**随做随写**进 `CURRENT.md`：做完一条立刻记结论和证据 ——
会话断在第 3 条竖切时，新会话靠这张表接手，不用重做、也不用轻信半成品。
上下文吃紧就先落盘断会话，**不许压缩第④步** —— 赶工的收尾看起来和正常交付一模一样。

派工规则见 §4，干活规矩见 `my-loop-builder`。

### ④ 亲手验收（只做这一次）

拉人之前自己先过三层，**下层不过不许进上层**：**静态**（构建 / 类型 / lint）→
**全量回归**（唯一一次）→ **锚里每条数据流各跑一遍端到端**。最后一层顶不掉：
单测各自 mock 各自过，接口不匹配、状态传不过去这类边界缺陷一个都抓不到。
然后拿锚**逐条对**：**过 / 没过 / 没法验**。第三种单独列，**不许混进「过」**。
**必须真的把它打开看一眼。** 退场再扫一眼：无调试残留、`CURRENT.md` 写完了、启动路径还能跑。

摆给人的报告要**短**：第一句是结论，然后锚的逐条表、原始输出在哪个文件，过程不用铺。
计划外的改动逐条说明。摆完，**停**。
人在这一步抓到 auditor 该抓没抓的，当场把它沉淀成一条自动检查或角色卡规矩 ——
不沉淀，同类漏网就一直靠人兜底。

## 3. 人全程只被打扰两次

**这一节优先级最高。搞错了，整套东西会变成骚扰。**

| 什么时候 | 找不找人 |
|---|---|
| ① 确认锚 | ✅ 找 |
| ② 列反例 | ❌ 写进 `CURRENT.md`，人回头能翻 |
| ③ 每一轮红→绿 | ❌ **绝对不找。** TDD 是子代理内部的事 |
| ③ 每条竖切做完 | ❌ 主 agent 自己核验（磁盘核实 + 定向测试） |
| 撞上决策表 / 动结构 / 影响大 | ✅ 找（例外，见 §6，不是常规节奏） |
| ④ 交付前总验收 | ✅ 找（唯一一次全量回归、唯一一次人扫测试注释） |

人中途问「做完了吗」，答的是**这条竖切的证据** + 还剩几条，**不是拉起总验收**。
分不清是不是最后一条，就问一句「这是最后一条了吗」——比白跑一次全量回归便宜。

## 4. 派工

**一条竖切一个一次性子代理，不定义身份、只派任务。**

```
你：只拿着 锚 + 竖切表 + 每条的结论 + 决策表
 ├ VS-1 → my-loop-builder（一次性）
 ├ VS-2 → my-loop-builder（读到 VS-1 更新后的 SHARED.md）
 └ 验证 → my-loop-auditor（只读，必须是另一个）
```

**auditor 之后的路由要走显式的**：过 → 下一条竖切；不过 → 返工单派新 builder；
**同一条竖切两轮不收敛 → 停，升级给人**（走 §8，别自己耗第三轮）。
`BLOCKER` / `MAJOR` 未清零不许当「过」往下走，`MINOR` / `INFO` 列进已知限制 ——
这条回退边不写死，卡死的竖切要烧掉一下午才被人发现。

**上下文污染的来源不是竖切多，是实现细节回流到你这里。** 你只需知道「做完没有、证据是什么、
有没有撞决策表」。交接损耗由 `.my-loop/SHARED.md` 抵消 ——
那是竖切之间唯一的通道，只写「猜错了两边就对不上」的东西。

**派工单只给四样**：工作目录 · 可读文件白名单 · 这条竖切的锚、怎么验、做完人能看到什么 ·
边界（含**明确不做什么**）。
**不许夹带答案** —— 自检一句「如果它照抄我这段话，它算干活了吗？」算，就删掉。
例外：返工单可以给精确修复清单。

**够门槛的竖切先过一道签名**（>150 行 / 新建模块 / 引入新的跨边界数据形状）：
子代理先交调用点 + 签名 + 四个数，你对着阈值过一遍，不过就打回。**人不参与。**
够不上的直接开写。细则在 builder 卡。

改动小到「派工单比代码还长」就自己做完。收活时你是 reviewer 不是打字员：
看真实输出、不听转述、**主动提反例**。

## 5. 决策表

`.my-loop/DECISIONS.md`（兼容旧路径 `.reins/DECISIONS.md`）。
SessionStart hook 每次会话自动注入 —— 这是全套里唯一的脚本，它只搬运不判断。
理由很窄：**agent 没法在会话开始前往自己的上下文里塞东西。**

**一条决策 = 一句话**，含三样：**定了什么 · 别做什么 · 为什么**。
对比过方案才拍的板，把**被否决的方案**带上一嘴 —— 决策反转的样子是：
下个会话拿着同样的信息，把你否决过的方案重新发明出来。

> `路由用语义路由，别再加正则规则 —— 之前堆正则导致路由效果很差`

长了就没人写，没人写就等于没有。门槛：**重犯一次会疼的**才写。

**守卫**（可选但很有用）标这条靠什么防住被改回去：
`结构 文件:行号`（最强，错误写法调不通）> `测试 文件:行号`（改错了变红）>
`仅文档` > `无`。**后两者 = 裸奔，是最容易被下次会话推翻的。**

四个读写时机 = 四步：**①读**（有无冲突）· **②读**（历史坑是最好的反例来源）·
**③撞上就停**（说哪条冲突，让人裁，**不许自行修正**）· **④写回**。

## 6. 三条不可省的检查

**① 测试结论不能由写测试的人给，而且光看结论挡不住「空过」。**
每条测试带 `【测什么】`/`【怎么算红】` 两行注释（格式见 builder 卡）。
第二行是可证伪声明 —— 人扫一眼就知道这条测试有没有意义。
**只在第 4 步做一次**：人扫注释 → 挑 2–3 条让它当场改坏验证 → 人自己跑全量。
贴原始输出，不贴结论。预测 ≠ 实测 → 立刻返工。

> 测试会空过：一条「重复提交不产生两次副作用」显示 pass，
> 但那个实现根本没有并发控制，重放当然不冲突 —— 它测了个寂寞。

**② 打开它看一眼。**
> 一行 CSS 注释里嵌了 `/* */`，注释提前结束吞掉整个 `:root{}`，页面全塌。
> 绕过了 176 条验收标准、19 个契约、134 条测试、5 道门禁 —— 因为没有测试渲染像素。

自动化只能验证你想到要验证的东西。能脚本化的就脚本化（起服务 → 抓页面和样式表 →
去注释后检查关键变量块还在 → 截图），但**必须有一个人真的看**。

**③ 接管必须记录。** 你替角色亲自干了活，在决策表记一条。
**接管可以，隐瞒接管不行** —— 流程越重，人在压力下接管的概率越高。

## 7. 简单是要主动维持的

**实测**（同一功能、同样 11 类能力、12 条探针结果完全打平）：

| 直接写 | 走流程 A | 走流程 B |
|---|---|---|
| 2050 行 | 3456 行（1.7×） | **5461 行（2.7×）** |

2.7 倍的代码换到一模一样的结果，而且「开箱可运行」还输了。

**派工单里别写「要可扩展 / 要健壮 / 要通用」** —— 这三个词是过度设计的触发器，写具体约束代替。
执行侧的五条规矩在 builder 卡，审计侧在 auditor 卡。

---

## 8. 什么时候停下来问人

只在这几种：**影响大**（改了方向后面一串跟着改）/ **动结构**（接口、数据形状、公共依赖）/
**可能引入新 bug**（无测试覆盖的老代码、并发、事务、缓存）/ **与决策表冲突**。

动作：摊开选项 + 每个的代价 + 你的推荐，然后挂起。

**门槛之下不要停**：用默认值直接做，但把用了什么默认值说出来 ——
说一句成本是零，停一次的成本是打断。

自检：**一次「停」如果解释不出「不停会怎样」，那次停就是仪式，删掉。**

---

## 9. 契约

只在**跨边界**时才写，只写「猜错了两边就对不上」的：字段名、类型、必填性、上限、状态码、错误码。
**一个文件**，不拆。改契约必须先于改代码。单人单模块就根本不写。

---

## 10. 文档：仓库是唯一事实来源

**agent 看不到的信息等于不存在。** 口头拍板的、聊天记录里的、上个会话脑子里的，
下个会话只能拿自信的猜测去填 —— 猜错的样子和正常干活一模一样。所以：
拍板进决策表、进行中的状态进 `CURRENT.md`、跨竖切约定进 `SHARED.md`，别处说了不算。

**入口短，专题深。** 项目根 `CLAUDE.md` 是路由器不是百科全书：概览 + 三条命令
（启动 / 测试 / 验证）+ 少数硬约束 + 指向专题文档的链接。知识**靠近代码**放 ——
模块目录下 50 行的 `ARCHITECTURE.md`，胜过远处 500 页。入口塞成巨型文件的下场：
关键约束死在中间、铁律和口味混在一起、矛盾攒多了 agent 随机挑一条执行。

**拆分的判据和动作**（不是原则，是要执行的）：往入口加任何一段之前先问 ——
**每个会话都需要读它吗？** 不是，就放专题文档，入口只留一行链接：
按「只在做某类任务才需要」切主题，50–150 行一份，放得越近越好
（模块目录的 `ARCHITECTURE.md` > `docs/主题.md` > 入口里多一段）。
**入口超过约 200 行 = 已经病了**：当场把「非每会话必读」的段搬出去，拆完用五问复验。
状态类永远不进入口：进行中状态在 `CURRENT.md`、拍板在决策表、跨切约定在 `SHARED.md`。

文档的验收是**全新会话测试**：开个新会话只看仓库，五问能不能答上 ——
**这是什么 / 怎么组织 / 怎么跑 / 怎么验证 / 做到哪了**。答不上哪问，补哪问；
过期的段落当场重追或删掉（§12 第一条）。

## 11. 初始化（单独做完，不掺一行业务代码）

初始化和实现混在一起，你会天然倾向先写代码、牺牲基础设施 ——
代码是立刻可见的产出，基础设施的价值要到下个会话才体现，而那时已经晚了。

```bash
cp -Rn "${CLAUDE_SKILL_DIR}/assets/project-template/." .
```

装进去三个文件：`.my-loop/DECISIONS.md`（决策表）· `SHARED.md`（竖切间的接头暗号，
没有共享就删掉）· `CURRENT.md`（这次变更的工作面）。

**再往项目根 `CLAUDE.md` 追加一段触发块**（正文在 `assets/claude-md-block.md`，
追加方式见 `/my-loop-init` 第 2 步，必须幂等、只追加不覆盖）。

> 这是本手册唯一允许「预铺」的东西，理由很窄：**新会话里能被保证读到的只有 `CLAUDE.md` 和
> SessionStart hook，而 hook 在决策表为空时是静默的 —— 刚装完的项目决策表就是空的。**
> 不写这一段，新项目开一个新会话 = 零 my-loop 上下文，模型当普通项目直接开写。
> 也因此这一段是「一条规矩只写一处」的**故意例外**：分级规则必须在 skill 加载之前就能读到，
> 否则「分级为 minor 才加载」是个死循环。所以它只写触发、分级分叉和一行文档纪律
> （守住它自己所在的入口文件不长膘 —— 改文档常被判 trivial，不加载手册，§10 管不到），
> **不复述手册**。

**装完文件不算完，环境要真跑通**：找到（或问人）**启动 / 测试 / 验证**三条命令，
各真跑一遍、至少跑通一个现成测试，把三条命令写进项目根 `CLAUDE.md`（已有就核对，不重复写）。
空项目没得跑就写「暂无」，**不许装跑过**。git 仓库就打一个初始化检查点。

验收口径四条：**能启动 · 能测试 · 能看进度 · 能接手**（最后一条用 §10 的全新会话测试对）。
装完 `ls` 核实、**打开 `CLAUDE.md` 末尾看一眼**，别只看退出码。
然后告诉用户：**以后直接说需求就行，不需要打任何命令。**
除触发块和三条命令外，**不预铺别的目录、不预铺模板。**

SessionStart hook 已在用户级 `settings.json` 配好，无需每个项目单独配。

## 12. 三条自检

- **一张过期的图/文档比没有更危险** —— 它让人自信地做出错误判断。
  碰了它描述的那一跳，要么当场重追，要么删掉。
- **如果你在「按流程走」，那就已经用错了。** 应该每一步问「不做这步会漏掉什么」，答得上来才做。
- **「不做会漏什么」吵不出结果时，做实验收尾**：禁用那个环节跑一次真实变更，
  质量不退化就永久删。论证吵不赢的，实证一锤定音。

> 这份手册不该长出模板、编号、状态机和必填表格。**长出来了，就把它砍回去。**
