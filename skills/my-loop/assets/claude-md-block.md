## 开发方式：本项目用 my-loop

**收到任何开发 / 改动请求，第一件事是分级并把分级说出来**，不要先动手写代码，
也不要改用 dev-s / brainstorming 等别的开发流程 skill。

- `trivial`（只影响本处、错了不牵连别人）→ **直接改完**，不加载 skill、不进循环，做完提一句
- `minor` / `major` → 先加载 `my-loop` skill 读手册，再按四步走：
  对齐锚 → 反例 → 竖切执行 → 亲手验收。**锚要人点头才开工，不设例外**
- 判不准就问「这个改动如果出错，最坏会怎样？」——
  影响契约 / 数据 / 权限 / 钱 / 隐私 = `major`；只影响本模块 = `minor`
- 开工前看一眼 `.my-loop/CURRENT.md`：**非空 = 有进行中的变更**
  （做到哪、证据、下一步都在里面），先读它再动，别当新变更重开
- 已拍板的决策在 `.my-loop/DECISIONS.md`，撞上了**停下来让人裁**，不许自行修正
- 往本文件加内容前先问：**每个会话都需要读它吗？** 不是就放专题文档、这里留一行链接
  （本文件超 200 行 = 该拆了）
