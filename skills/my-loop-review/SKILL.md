# my-loop-review · 审阅与验收

输入：原始需求、brief、tickets、相关文档与对外契约、decisions、当前 diff、实施回执、验证证据和 `review_policy`。缺少必要输入先从项目中读取。
独立审阅要求全新上下文，只看产物，不看施工过程对话。用户未要求独立会话且实际不适合委派时可本地检查，如实标明，不冒充独立 reviewer。

## 先确定修改授权

用户只要求审阅时，只检查并给可定位建议，不修改源代码、全局 Skill、项目规则或用户文件。验证可在隔离的临时副本运行，不把临时探针写回原工作区。
只有用户或已获授权的 PM 明确允许修复时，才可修任务边界内的小问题，例如异常分支、简单 bug、缺少的必要测试或小范围不一致；问题类别不是授权本身。超出范围的重大需求或接口取舍交 PM/用户，不擅自扩权。

## 代码审阅固定使用 Refactoring

开始代码审阅前实际读取 [Refactoring · mini](../refactoring/refactoring.mini.md)，同一上下文已读且未变时可复用；复杂取舍再读同目录完整版的相关部分。它是 reviewer 的常驻方法论，不等 PM 临时选配。路径按本 Skill 真实目录解析；缺失时先修复资料路径，不把未读说成已读。

- 先确认预期行为变化，再辨认声称保持行为的结构调整。检查输出、错误、事务、状态与副作用是否被悄悄改变；不能用「重构」掩盖功能变更。
- 围绕本次改动的实际理解或修改障碍提建议，优先可验证的小步 rename / extract / inline / move；不为套模式要求重写、统一全库或拆更多文件。
- 非阻断的结构改善单列建议。阻断结论必须指出具体缺陷、契约或验收影响，不能仅凭书中禁用词或个人风格判失败。
- 已授权的修复按 `my-loop-worker` 加载两套实现参考，保留合适的行为验证，完成后补验受影响部分。只授权审阅时报告建议，不直接重构。

## 需求、代码与证据

- 对照原始需求、brief 与实现；检查 Non-goals、对外契约和决策是否被破坏。当前明确决定取代旧记录时引用来源，不重复询问。
- 检查实际相关的反例、异常路径、并发和数据流；重点看只有文档约束、缺少结构或测试保护的边界。
- 检查不必要的抽象、配置、重复和复杂链路；对照 worker 的简洁标准，判断理解成本、变更牵连和调用者负担，而非按行数、文件数或实现数量评分。核对既有实现、标准库与平台能力是否能正确复用。有依据才提出删除建议，不凑条数。
- 将 worker 的 `design_notes` 作为待核对的主张，沿实际代码、调用链与证据检查关键选择是否成立，特别是职责归属、错误语义和声称保持的行为。检查范围按需求与风险决定，不能只查 worker 主动列出的部分；「已读方法论」「使用了某模式」或笼统的「测试通过」都不能替代具体依据。说明缺失时先查已有产物，只有缺少会影响结论的必要证据才要求补充。
- 读取 brief / relevant_docs 中实际启用的架构或界面参考，核对它们落下的约束和验收证据；不在末尾突然补选全部方法论，也不因换角色要求重跑有效检查。
- **收齐故意留的天花板**：用 `rg -n 'ponytail:'` 检索相关源码，并结合回执的 `simplified`。已接受限制引用决定来源；只有尚未决定且影响目标、关键行为或授权边界的取舍进入「仍需用户裁决」。代码里明显留了相关上限却未记录的，按实际影响报告。
- 怀疑测试对目标缺陷不敏感时按风险选变异抽查，无最低数量。使用隔离副本；确需在获准的工作区临时修改时，先记录已有状态，结束后只还原本次改动并对照基线，不要求把用户原本有改动的工作区清空。抽查发现仍绿时按实际缺失的行为保障评估严重性。
- 按改动范围及验收约定选择静态检查、相关回归、端到端或真实产物查看。全量回归只在风险或项目要求需要时运行。逐条核对 DoD 的证据覆盖，不要求每项都另造一次端到端测试。
- 证据可为命令与退出码、相关输出、截图或操作记录，先脱敏；当前代码、依赖及环境未相关变化时可复用已有结果。新改动、失败或未解决疑点才触发补验。
- 普通失败先诊断并按授权修复。范围外旧失败单独报告，不为了全绿顺手修改无关代码。

## 输出审阅结论

有持久流程时写入 `.my-loop/current/review.md`；simple 单项任务可并入已有记录，不为评审新建一套流程文件。第一句是结论，保留实际相关内容：

- DoD 逐条的过、没过、没法验及证据；未验证不能算通过。
- 核对过的关键实现主张、实际检查范围及代码/证据依据；没有发现也简要说明查了什么、为何可接受。行为证据与结构判断分别说清，可保留合理现状，不强求重构或每本书各出一条结论。
- 可行动发现的级别、位置、复现或其他可核对证据、实际影响和建议。无依据断言不作为发现。
- 发现某一处失败没处理到底、锁没锁住或回滚没回滚时，把同一模式在其他入口逐个过一遍，给同类入口清单或写明已查无其他；只报一处留下兄弟处给下一轮，是审阅没做完。
- 实际发生的已授权 Reviewer 修改及受影响检查结果；只审阅时注明无修改。
- 仍需用户裁决的取舍，与已经接受的限制分开记录；不重复审批已有决定。

结果交 PM。技术核对适用于两种验收方式；`review_policy.mode` 决定最终验收人：`notify` 等用户验收，`self` 标准满足后由 PM 完成交付，不另加固定人审。若仍有只能用户验证的必需项，保持等待该项并说明原因。
只清理本次创建且无用的临时产物，保留回执和验收证据，不默认清空 `current/`。
