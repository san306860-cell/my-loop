# 技术简报

按本任务实际规模填写。已有授权直接复用，只对影响目标、关键行为或权限的剩余歧义等待决定。

**分级**：simple / medium / big / bug，由 PM 根据证据决定。

**Goal**：用户或系统的可观察结果。

**Definition of Done**：

| 标准 | 检查方式与预期结果 | 证据 | 结论 |
|---|---|---|---|

**Boundary / Non-goals**：本次范围与明确不做的事项。

**Constraints / Known**：契约、限制与已确认事实。接口只钉 worker 改不动另一边的——对外 API、别的仓库或客户端在用的接口、共享 DB schema、第三方回调格式——写到字段级；仓库内部接口由 worker 选择，不在这里定死。

涉及架构或网页视觉方法时，在上面记录具体问题、资料链接、本次约束与验证方式。worker/reviewer 常驻方法由各自 Skill 规定，不在这里重复抄写清单。

**Unknowns**：剩余歧义、是否阻塞及可以继续的独立工作。

仅当关键决定互相依赖时，按 PM 的 Wayfinder 适配补充「问题 / 依赖 / 如何获得答案 / 状态与证据 / 阻塞的工作」。答案引用唯一决策来源，不另建施工票系统。

**Decisions**：引用唯一决定来源；新决定区分用户确认、项目约束和 PM 在授权内的工程选择。

**验收方式**：记录用户选择的 notify / self 和本任务标准；方式只决定最终验收人，必要技术核对按 PM 规则执行。未确定时明确待决定，不能把待决定当默认同意。

**仅 Big 填 · 方案形状**：动哪几块、数据怎么流，一句话级。只为让票切得一致，不是实现步骤。

**仅 Big 填 · 测试边界**：在哪下测试。

## Bug Brief（bug 任务替换上面的通用内容）

现象 / 复现或现有证据 / 根因与可信程度 / 修复边界 / 不可破坏行为 / 验证方式 / 未验证项。
适合行为回归时保留修复前红、修复后绿；其他情况说明实际有效的证据，不伪造复现或补无价值测试。
