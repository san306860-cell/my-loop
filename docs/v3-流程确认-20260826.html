流程确认稿：你手动触发的四个阶段

流程全 · 思想全 · 实现薄

v2 的脑子原封不动，换个身体：所有规矩写在文件和提示词里，会话的开、切、关交给 Herdr 和你的手。第一版一行调度代码都不写。

人需要你出现的时刻（除此之外都不打扰你）
AI 会话在 Herdr 里开的模型会话
文件落在项目 .my-loop/ 里的东西
进门前 先掂量这事多大v2 老规矩，不变
  • 小事（改一行文案、改个常量，出错也不影响别人）：不进 my-loop，直接改完说一声。
  • 会影响别人的事，才走下面四个阶段。判断口径就一句：这事做错了，最坏会怎样？
阶段 0 init每个项目只做一次 Claude
  • 在项目里铺好 .my-loop/ 协议文件（清单见下文）。
  • 找到「启动 / 测试 / 验证」三条命令，各真跑一遍，写进项目说明。跑不通不算装完。
  • 不掺一行业务代码。
产出：一个换谁来都能接手的空工作面。
找你：装完告诉你一声，就完了。
阶段 1 align 对齐人参与最多的一段 Fable 对齐Opus 写文档
  • 你用大白话说需求。强模型读项目、读决策表，然后用人话追问：没说清的、边界在哪、你可能没想到的风险。
  • 人它复述一遍理解 → 你说「理解对了」才往下走，不设例外。这一步押的是最贵的错误：方向做错了。
  • 定大小：简单 → 对齐完直接做，不写文档；中等 / 大 → 继续往下。
  • Opus 写文档：只更新这次真正涉及的；接口约定收在一个文件里，不拆。
  • 拆任务清单 tickets.json：每条任务做完，你能亲眼看到一个变化；每条自带「拿什么验」。
  • 人反例表：这个设计在什么输入下会塌（极端值 / 两人同时操作、断网重试 / 上游挂了）——每条由你当场拍：挡住，还是接受。实验证明：没人在场时 AI 一律选「接受」。
产出：brief（目标 + 验收标准 + 明确不做 + 反例表）、文档、tickets.json、state.json。
找你：两次，同一场坐完（点头 + 拍反例）。
阶段 2 build 快速实现 Herdr → agy
  • 你在 Herdr 里拉起 agy（快模型），按清单顺序干活，同一时刻只做一条。
  • 它读四样：这条任务 + 相关文档 + 施工规矩（constitution）+ 相关决策（相关的给全文，其余给一行标题，保证没有决策彻底看不见）。
  • 施工规矩的核心：最简单的正确实现；不顺手多做；不为「以后可能要」写代码；每条测试写清「测什么、怎么才会红」。
  • 完成的定义：贴出验收命令的真实运行输出。没输出不算完成；验不了的老实写「没法验」，不许混进完成里。
  • 状态随做随写回 state.json —— 断了会话、换了模型，照着文件就能接上。
  • 人只有两种情况找你：撞上已拍板的决策，或同一个错连改两轮还不行。用人话把选项和代价摆给你，你拍板，记进决策表，继续。
产出：代码 + 每条任务的输出证据 + 更新后的进度。
找你：顺利的话 0 次。
阶段 3 review 强审 Herdr → 全新会话（GPT‑5.6 Sol / Opus）
  • 你在 Herdr 拉一个全新的强模型会话——它没看过施工过程，只看结果：原始需求、brief、文档、决策表、代码改动、测试输出。
  • 查代码：需求做对没有、有没有越界多做、有没有过度设计、异常和并发处理。外加一手抽查测试是不是真的在测：把实现故意改坏一处，看测试红不红。优先抽 worker 自己报的「最没把握的地方」。
  • 跑系统：集成、回归、端到端，把页面/产物真的打开看一眼。
  • 小毛病它顺手修掉，但每一笔修改都记录在案，报告里单独列出——你验收时优先看这里（防它既当运动员又当裁判）。
  • 人大问题（需求理解错了 / 要改约定 / 方向冲突）→ 用人话找你定夺。
产出：一份人话报告：第一句就是结论，然后验收标准逐条（过 / 没过 / 没法验）+ 原始输出在哪。
终点 你亲手验收 → 才收尾 人
  • 人你拿着报告，打开真实产物看一眼，亲手跑一遍关键操作。不满意 → 打回去修。
  • 你点头之前，谁也不许删东西。点头之后才收尾：
  • 沉淀：重要决策写进决策表（带「靠什么防住被改回去」和「否决过什么、为什么」）；有长期价值的文档转正。
  • 清理：临时文件、施工产物、用完的任务清单，清干净。
  • ELI5 总结：这次解决了什么 / 以前怎样 / 现在怎样 / 关键决策是什么 / 还剩什么风险。
两条线贯穿全程
决策表贯穿对齐时读它 → 施工撞上它就停 → 审查拿它对 → 收尾写回它。新会话、新模型进来，第一件事就是读到它。
ELI5 贯穿所有找你说话的地方——追问、卡住、报告、总结——一律说人话，第一句先给结论，不许堆黑话。
这一版里，哪些是你拍的、哪些是我补的

你拍的板

  1. 决策表用 JSONL，加两个字段：靠什么防住被改回去 / 当时否决过什么、为什么
  2. 进度文件直接上 JSON（老项目先留 md）
  3. Herdr 第一天进体系，你手动开、切会话
  4. 四个阶段全部你手动触发：init / align / build / review
  5. Opus 写文档 → agy 实现 → 全新会话强审
  6. ELI5、KISS 贯穿；流程全、思想全、实现薄
  7. 你验收通过，才允许收尾清理

我从 v2 补回的防线（都有踩坑或实验背书）

  1. 先分级再进门，小事不进流程——防你哪天嫌烦绕开它
  2. 完成 = 贴真实输出——防 AI 谎报完成，坏地基传染下游任务
  3. 反例由你当场拍挡 / 接受——实验实测：没人在场 AI 一律选接受
  4. 审查时故意改坏实现，抽查测试会不会红——防测试测了个寂寞
  5. worker 自报「最没把握处」，审查优先抽那里
  6. reviewer 顺手修的每一笔都记录、你优先看
  7. 「没法验」单独列，永远不许混进「过」
  8. 规矩只写一处：constitution 是唯一出处，别处只引用
项目里只多一个 .my-loop/ 目录
constitution.md施工规矩的唯一出处，每个干活会话都带着。很短。
decisions.jsonl拍过板的决策，一条一行。带 guard + rejected 两个字段。
state.json tickets.json进度和任务清单，机器原语。新项目直接 JSON，老项目先留 md。
current/brief.md这次变更的工作面：目标、验收标准、明确不做、反例表。给人和模型读的。
current/review.md审查报告 + reviewer 的修改清单。验收完随收尾清掉。
