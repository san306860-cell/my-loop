> **实例是项目的，模式是我的。**

## 静默降级

**是什么**：出问题时不报错，而是悄悄退回一个「能跑」的次等路径。
后果不是崩溃，是**正常路径和故障路径长得一模一样**，人根本不知道自己在故障里。

**为什么危险**：它消耗的是信任。你以为配好了，界面毫无变化，
只能怀疑「压根没接入」—— 而占位输出往往长得很像真输出。

**已知发作**（agentv / a-reins-mvp）：
- 没人调 `load_dotenv`，`.env` 是死配置 → 回落假客户端，七步照跑，每个字都是占位符
- 没配 key 时 `fallbackPlan` 硬编码返回同一套方案，不管用户输入什么

**疫苗配方**：
1. 降级路径必须在**界面上显式标出来**（一个 `configured` 徽标、一个 `source: demo` 标签）
2. 验收要**两个方向都钉**：该降级时必须降级，该读到时必须读到 ——
   只钉一边的守卫，可能是靠「配置永远失效」成立的

## 死机制

**是什么**：一个从建成起报警路径就没执行过的检查。它一律表面全绿，
因为它**根本不会响**。

**为什么危险**：它比没有检查更坏 —— 没有检查你还知道自己没护栏，
死机制让你以为有。

**已知发作**（agentv）：
- `TID` 规则配了但没进 `select`，`ruff check` 永远不报分层违规
- `check_scanner_readonly.py` 的含 `.` 正则分支从建成起没响过 ——
  **死在防死机制的检查器自己身上**
- 缰绳自测首跑 34/34 全绿，变异测试当场抓出禁区那条是死用例
  （它因为**错误的理由**变红：那个文件同时也不在允许清单里）

**疫苗配方**：
1. 写下「这条由 X 强制」的同一轮，造最小违规喂给 X，**亲眼看它报错**
2. 再喂合规样本确认不误报
3. **断言报警的理由，不只断言红绿** —— 红了但理由不对，等于没测
4. 引爆样例不许扔，沉淀进自测；**检查器自己也要被检查**（变异测试）

## 第二份真相

**是什么**：同一个事实被存了两处（或抄了两遍）。改了一处、另一处静默过期。

**为什么危险**：这种漂移**没有任何测试能自动抓到**，
因为两边各自都自洽，只是彼此不一致。

**已知发作**（agentv）：
- `stale` 想存成字段 → 应该由「我的定稿时间 < 上游的定稿时间」算出来
- 依赖图想在前端再写一份 → 只在 `STEP_DEPS` 定义一次，反向表由它推导

**疫苗配方**：
1. 能推导的绝不存储
2. 必须双实现时（前后端各一份解析器），喂**同一份样本**、断言**同一组结论**，
   一边改了另一边立刻红
3. 派生物标注它是从哪算出来的

## 假警报

**是什么**：检测器精度不够，天天报不是问题的问题。

**为什么危险**：**假警报会训练人忽略警报。** 到那时真违规也拦不住了。
更隐蔽的变体是：**拿人的纪律去补检测器的精度** ——
「以后起文件名前先念一遍」这种规矩，是护栏欠下的债。

**已知发作**（agentv）：
- 裸 `sk-` 判据在第三方目录扫出 508 处误报 →
  当时的应对是**把文件改名绕开它**，还写成一条要人记住的纪律
- 换成「`sk-` 之后有一长串不被连字符打断的字符」后：误报归零、排除项归零、那条纪律直接删掉

**疫苗配方**：
1. 判据要贴着**真目标的形状**，不是贴着它的前缀
2. **能用检测器精度换掉人的纪律，永远换**
3. 检测器要三向钉住：真货必抓、像货必须沉默、干净目录的退出码要对

## 顺序依赖

**是什么**：两件事必须按特定顺序发生，顺序反了不报错，只是**读到旧值**。

**为什么危险**：症状出现在很远的地方，且看起来像别的问题。

**已知发作**（agentv）：
- 验收脚本必须**先设环境变量、再 import backend**，反了就读到默认值
  （那排 `# noqa: E402` 就是为此存在的，不是随手加的）
- `.env` 放模块级读 → 九个没设 `LLM_FAKE` 的验收脚本一跑就打真模型，跑掉 $0.60；
  放进 lifespan 后：真服务读得到，裸 TestClient 永远读不到

**疫苗配方**：
1. 把顺序变成**结构**：放进只有真服务才会走的钩子里，而不是靠调用者记得
2. 顺序敏感的地方写注释说明**为什么是这个顺序**，不只说做了什么
